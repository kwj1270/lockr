# Research

주제를 분석하여 스포츠 도메인, 기술, 프로젝트 지식을 Google 검색과 코드 탐색을 통해 조사하고 요약 리포트를 제공한다.

## 사용법

```
/research <조사할 주제>
```

## 1단계: 주제 분류

사용자가 입력한 주제를 분석하여 카테고리를 판단한다. 복합 주제는 여러 카테고리에 걸칠 수 있다.

| 카테고리 | 예시 | 검색 전략 |
|----------|------|-----------|
| **스포츠 도메인** | 축구 규칙, 클럽 운영, 포메이션, 출석 관리 | 한/영 양쪽 검색, 공식 규정·협회 사이트 우선 |
| **기술** | Spring 패턴, jOOQ 최적화, CQRS, Event Sourcing | 영어 위주, 공식 문서·GitHub 이슈 우선 |
| **프로젝트** | lockr 코드베이스의 구조, 기존 구현 방식, 패턴 분석 | 코드 탐색(Grep/Glob/Read) + 필요시 외부 검색 |

## 2단계: 검색 및 수집

### 공통
- 최소 2~3개의 서로 다른 검색 쿼리를 사용한다
- 검색 결과가 부족하면 키워드를 변형하여 재검색한다
- 필요시 WebFetch로 상세 페이지 내용을 확인한다

### 스포츠 도메인
- 한국어와 영어 양쪽으로 검색한다 (스포츠 용어는 영어 자료가 더 풍부한 경우가 많기 때문)
- 공신력 있는 출처를 우선한다: FIFA/KFA 공식 규정, 스포츠 협회, 전문 매체
- 한국 동호회 문화 특성을 고려하여 해외 사례를 그대로 적용하지 않는다

### 기술
- 공식 문서를 최우선으로 참고한다 (Spring docs, jOOQ docs 등)
- Stack Overflow, GitHub Issues, 기술 블로그 순으로 신뢰도를 판단한다
- 버전 호환성을 확인한다 (프로젝트에서 사용 중인 버전 기준)

### 프로젝트
- Grep, Glob, Read 도구로 코드베이스를 탐색한다
- 기존 구현 패턴과 컨벤션을 파악한다
- 필요시 docs/domains/ 아래 도메인 컨텍스트 문서를 참조한다
- 외부 검색이 필요하면 기술 카테고리의 전략을 병행한다

## 3단계: 리포트 작성

```
# [조사 주제]

## 카테고리
스포츠 도메인 / 기술 / 프로젝트 / 복합

## 핵심 요약
- 3~5줄로 핵심 내용 요약

## 상세 내용

### [세부 주제 1]
- 조사 내용

### [세부 주제 2]
- 조사 내용

## lockr 적용 제안
- 이 프로젝트 맥락에서 어떻게 활용할 수 있는지 구체적으로 제안
- 기존 코드와의 관계, 변경이 필요한 부분 등

## 출처
- [출처명](URL) 또는 [파일명](파일 경로)
```

## 주의사항

- 검색 결과의 날짜를 확인하여 최신 정보인지 판단한다
- 규정이나 규칙은 해당 협회/연맹의 공식 자료를 우선한다
- 불확실한 정보는 "확인 필요"로 표시한다
- 프로젝트 카테고리에서는 코드를 직접 확인한 내용과 추측을 구분한다
